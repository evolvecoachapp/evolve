## Goal

Transform every coaching interaction into a complete Explainable Coaching Session.

The user should never receive only a text response. Every coaching request produces a structured coaching session built from existing EVOLVE architecture.

**No new reasoning engines. No duplicated logic. Compose existing domain services only.**

## Module

`app/src/features/coaching-session/composition/`

Extends `features/coaching-session` alongside Sprint 22.0 Coaching Session Runtime (lifecycle). Does **not** replace the lifecycle runtime.

- Models: `CoachingSession`, `CoachingSessionContext`, `CoachingSessionEvidence`, `CoachingSessionDecision`, `CoachingSessionRecommendation`, `CoachingSessionInsight`, `CoachingSessionExplanation`, `CoachingSessionSummary`, `CoachingSessionConfidence`, `CoachingSessionResult`
- Services (single responsibility): `collectEvidence`, `collectTimelineContext`, `collectDecisionContext`, `collectRecommendationContext`, `collectInsightContext`, `collectExplanationContext`, `buildSessionSummary`, `calculateSessionConfidence`, `validateCoachingSession`, `buildCoachingSession`, `ExplainableCoachingSessionService`
- Application API: `composeCoachingSession`, dashboard getters (`getLatestCoachingSession`, `getCoachingSessionSummary`, `getCoachingSessionEvidence`, `getCoachingSessionInsights`, `getCoachingSessionConfidence`), `validateExplainableCoachingSession`

**Does not:** persist to DB, introduce an event bus, run a scheduler, call an LLM, redesign UI, invent evidence, or replace Decision / Recommendation / Explainability / Timeline / Insights engines.

Sprint 22.0 runtime descriptor type remains `models/CoachingSession`. The explainable product artifact is `composition/models/CoachingSession` (exported as `ExplainableCoachingSession` from the feature root to avoid the name clash).

---

## Session Contract

Every immutable session includes: session id, timestamp, user request, conversation intent, evidence used, timeline references, decision summary, recommendation summary, insight summary, reasoning summary, expected outcome, confidence, related domains, context, summary, metadata.

---

## Confidence

Confidence is deterministic from evidence item count and source count.

Never generated by an LLM.

---

## Conversation

Every Coach Conversation turn internally builds an Explainable Coaching Session (`EXPLAINABLE_SESSION` stage). Conversation response message APIs remain compatible — no breaking changes, no UI redesign.

---

## Dashboard API (presentation only)

- Latest Coaching Session
- Session Summary
- Session Evidence
- Session Insights
- Session Confidence

No UI redesign.

## Composition Root

Registers `ExplainableCoachingSessionService` (depends on `CoachTimelineService` + `PlanHistoryService` + `ProactiveInsightsService`) and injects it into Coach Conversation.

Home Experience (Sprint 27.1) consumes the latest explainable session for the Home coach card ([HOME_EXPERIENCE.md](./HOME_EXPERIENCE.md), ADR-089).

Athlete Daily Brief (Sprint 27.2) consumes the latest explainable session for the Daily Brief coach message ([DAILY_BRIEF.md](./DAILY_BRIEF.md), ADR-090).

Weekly Coach Report (Sprint 27.3) consumes the latest explainable session for executive summary, recommendations, and evidence projection ([WEEKLY_REPORT.md](./WEEKLY_REPORT.md), ADR-091).
